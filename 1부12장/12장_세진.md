
# 12장 어노테이션과 리플렉션

## 어노테이션

- 코드에 메타데이터를 붙이는 도구
- 어노테이션 자체는 코드 동작에 영향을 주지 않음
- - 컴파일러, IDE, 라이브러리 등이 그 어노테이션을 읽고 행동을 바꿔야 의미가 생김.

```kotlin
@Deprecated("Use removeAt(index) instead.", ReplaceWith("removeAt(index)"))
fun remove(index: Int) { ... }
```

### 어노테이션 인자
- 컴파일 시점에 결정되는 상수만 가능!
  
사용 가능한 타입
- 기본 타입 (`Int`, `String`, ...)
- enum
- 다른 어노테이션
- 클래스 참조 (`KClass`)
- 위 타입들의 배열

```kotlin
@MyAnnotation(
    name = "test",
    type = MyType::class,
    tags = ["a", "b"]
)
class Foo
```

자바와 다른 점: 코틀린은 배열 인자에 `arrayOf(...)` 또는 `[...]`을 씀.

### 사용 지점 타깃

- 코틀린 프로퍼티 하나는 자바에서 여러 요소로 변환됨.
  - 어노테이션을 어디에 적용할지 모호해지는데, 이때 타깃을 명시함.

```kotlin
class Person(
    @field:MyAnnotation val name: String,    // 필드
    @get:MyAnnotation val age: Int,           // getter
    @param:MyAnnotation val email: String     // 생성자 파라미터
)
```

타깃 목록: `property`, `field`, `get`, `set`, `receiver`, `param`, `setparam`, `delegate`, `file`.

`file`은 파일 최상단에 붙임.

```kotlin
@file:JvmName("StringUtils")
package com.example
```

### 어노테이션 선언

```kotlin
annotation class JsonName(val name: String)
```

- 파라미터는 반드시 `val`. 본문 없음.
- 자바보다 간결함

```java
// Java
public @interface JsonName {
    String value();
}
```

```kotlin
// Kotlin
annotation class JsonName(val value: String)
```

### 메타어노테이션

- 어노테이션에 붙이는 어노테이션.

```kotlin
@Target(AnnotationTarget.PROPERTY)
@Retention(AnnotationRetention.RUNTIME)
annotation class JsonExclude
```

`@Target`은 적용 위치를 제한함.

`@Retention`

- `SOURCE`: 컴파일 후 사라짐
- `BINARY`: 클래스 파일에 저장, 리플렉션 접근 불가
- `RUNTIME`: 클래스 파일 저장 + 리플렉션 접근 가능 (코틀린 기본값)

### 어노테이션 파라미터로 클래스 받기

```kotlin
annotation class DeserializeInterface(val targetClass: KClass<out Any>)

data class Person(
    val name: String,
    @DeserializeInterface(CompanyImpl::class) val company: Company
)
```

`company`의 타입은 `Company` 인터페이스라 역직렬화 시 어떤 구현체로 만들지 모를 때,
`@DeserializeInterface`로 `CompanyImpl::class`를 지정.

타입이 `KClass<out Any>`인 이유???
- `KClass<...>` — 클래스 참조
- `out` — 공변. `KClass<CompanyImpl>`도 받을 수 있게
- `Any` — 어떤 클래스든 가능

### 어노테이션 파라미터로 제네릭 클래스 받기

```kotlin
interface ValueSerializer<T> {
    fun toJsonValue(value: T): Any?
    fun fromJsonValue(jsonValue: Any?): T
}

annotation class CustomSerializer(
    val serializerClass: KClass<out ValueSerializer<*>>
)
```

`KClass<out ValueSerializer<*>>` — `ValueSerializer`의 어떤 구체화든 받겠다

## 리플렉션

- 런타임에 클래스, 함수, 프로퍼티 정보를 동적으로 탐색하고 호출하는 기능
- 컴파일 시점에 이름으로 호출하는 방식의 반대.
  - `java.lang.reflect`: 자바 표준
  - `kotlin.reflect`: 코틀린 전용. 코틀린 고유 개념(프로퍼티, 디폴트 파라미터, 확장 함수 등)을 다룸
    - 코틀린 리플렉션은 별도 의존성(`kotlin-reflect.jar`, 약 2.5MB) 필요.

### 주요 인터페이스

#### KClass

자바 `Class`에 해당.

```kotlin
val person = Person("Alice", 30)
val kClass = person::class

println(kClass.simpleName)     // "Person"
for (prop in kClass.memberProperties) {
    println(prop.name)
}
```

자바와 변환 가능

```kotlin
val javaClass = Person::class.java
val kClass = javaClass.kotlin
```

#### KCallable

함수와 프로퍼티의 공통 상위 인터페이스.

```kotlin
interface KCallable<out R> {
    fun call(vararg args: Any?): R
}
```

#### KFunction

```kotlin
fun sum(x: Int, y: Int) = x + y

val kFunction: KFunction2<Int, Int, Int> = ::sum

kFunction.invoke(1, 2)   // 3, 타입 안전
kFunction(1, 2)          // 3
kFunction.call(1, 2)     // 3, 타입 검사 없음
```

`invoke`와 `call`의 차이
- `invoke`: 컴파일 시점에 시그니처 검증. 인자 개수/타입 정확해야 함
- `call`: 가변 인자로 받음. 타입 안전성 없음. 모든 KCallable에서 공통으로 동작

#### KProperty

```kotlin
class Person(val name: String, var age: Int)

val person = Person("Alice", 29)
val ageProperty = Person::age

ageProperty.get(person)        // 29
ageProperty.setter.call(person, 30)
```

### 리플렉션으로 직렬화 구현

JKid의 직렬화 함수. 객체의 모든 프로퍼티를 순회하며 JSON 문자열을 만듦.

```kotlin
private fun StringBuilder.serializeObject(obj: Any) {
    val kClass = obj.javaClass.kotlin
    val properties = kClass.memberProperties
    
    properties.joinToStringBuilder(this, prefix = "{", postfix = "}") { prop ->
        serializeString(prop.name)
        append(": ")
        serializePropertyValue(prop.get(obj))
    }
}
```

핵심:
- `obj.javaClass.kotlin`으로 KClass 얻기
- `memberProperties`로 모든 프로퍼티 순회
- `prop.get(obj)`로 값 읽기

### 어노테이션 + 리플렉션

위 직렬화에 `@JsonExclude`, `@JsonName`, `@CustomSerializer`를 통합.

```kotlin
private fun StringBuilder.serializeObject(obj: Any) {
    obj.javaClass.kotlin.memberProperties
        .filter { it.findAnnotation<JsonExclude>() == null }
        .joinToStringBuilder(this, prefix = "{", postfix = "}") { 
            serializeProperty(it, obj) 
        }
}

private fun StringBuilder.serializeProperty(
    prop: KProperty1<Any, *>, obj: Any
) {
    val jsonNameAnn = prop.findAnnotation<JsonName>()
    val propName = jsonNameAnn?.name ?: prop.name
    
    serializeString(propName)
    append(": ")
    
    val value = prop.get(obj)
    val jsonValue = prop.getSerializer()?.toJsonValue(value) ?: value
    serializePropertyValue(jsonValue)
}
```

`findAnnotation<T>()`는 해당 어노테이션이 있으면 반환, 없으면 null.

```kotlin
inline fun <reified T : Annotation> KAnnotatedElement.findAnnotation(): T? =
    annotations.filterIsInstance<T>().firstOrNull()
```

11장에서 본 `reified`가 여기서 활용됨.

### 역직렬화

역직렬화는 직렬화보다 복잡함. JSON 문자열을 분석해서 적절한 코틀린 객체를 만들어야 함. JKid는 세 단계로 진행됨:

1. 렉서: JSON 문자열을 토큰 단위로 분해
2. 파서: 토큰을 의미 단위로 조립하며 콜백 호출
3. 역직렬화 시드: 콜백을 받아 객체 빌더 구성

진입점

```kotlin
inline fun <reified T : Any> deserialize(json: String): T {
    return deserialize(StringReader(json), T::class)
}
```

`reified`로 호출자에서 `KClass`를 자동으로 얻음.

### callBy

`call`은 모든 인자를 순서대로 받음. 디폴트 값이 있는 파라미터를 활용 못함.

```kotlin
data class Person(val name: String, val age: Int = 0, val email: String? = null)

val constructor = Person::class.primaryConstructor!!
constructor.call("Alice")   // 인자 부족, 런타임 에러
```

`callBy`는 파라미터 이름으로 매핑해서 호출함. 누락된 파라미터는 디폴트 값 자동 적용.

```kotlin
fun callBy(args: Map<KParameter, Any?>): R
```

```kotlin
val nameParam = constructor.parameters.first { it.name == "name" }
val person = constructor.callBy(mapOf(nameParam to "Alice"))
// Person(name="Alice", age=0, email=null)
```

JSON에 일부 필드만 있을 때 `callBy`가 필수임. 맵에 없는 파라미터는 코틀린이 디폴트 값으로 채움.

`KParameter`의 `isOptional`로 디폴트 값 유무 확인 가능.

### 타입 변환

JSON은 모든 숫자를 동일하게 표현하지만 코틀린은 `Int`, `Long`, `Double`을 구분함. `KType` 정보로 적절한 타입으로 변환해야 함.

```kotlin
val paramType = param.type
val value = when {
    paramType.classifier == Int::class -> jsonValue.toString().toInt()
    paramType.classifier == String::class -> jsonValue.toString()
    // ...
}
```
