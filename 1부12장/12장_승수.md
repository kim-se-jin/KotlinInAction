## 12.1 어노테이션 선언과 적용

선언에 추가적인 메타데이터를 연관시킬 수 있다. 어노테이션이 설정된 방식에 따라소스코드, 컴파일된 클래스 파일, 런타임에 대해 작동하는 도구를 통해 접근할 수 있다.

## 12.1.1 어노테이션을 적용해 선언에 표지 남기기

어노테이션 적용을 위해 @와 어노테이션 이름을 넣으면 된다. 함수, 클래스 등 여러 코드에 붙일 수 있다.

JUnit의 @Test 어노테이션이 그 예이다. (인텔리제이는 @Test 를 실행가능한 어노테이션으로 인식한다)

@Deprecated 더 이상 쓰이지 않게 될 것임을 표시한다. (message, replaceWith, level 3가지 파라미터를 받는다)

어노테이션의 인자로는 기본 타입의 값, 문자열, 이넘, 클래스 참조, 다른 어노테이션 클래스와 배열을 쓸 수 있다.

클래스 : @MyAnnotation(MyClass::class)

다른 어노테이션 : @Deprecated(ReplaceWith(~~)), 골뱅이 생략

배열을 인자로 지정 : @RequestMapping(path = [”/foo”, “ /bar”]

또한 파라미터는 컴파일 시점에 알 수 있어야 하기 때문에 const val 키워드가 붙은 변수만 넣을 수 있다.

## 12.1.2 어노테이션이 참조할 수 있는 정확한 선언 지정: 어노테이션 타깃

사용지점타겟 : 어노테이션을 어떤 타겟을 선정할지 지정해야 한다.

프로퍼티는 get set 등 다양한 매핑을 갖는다.

get을 참조한다면 @get set을 참조한다면 @set을 사용한다

```kotlin
@get:JvmName("obtainCertificate")

class CertificateManager {
	@get:JvmName("obtainCertificate")
	@set:JvmName("putCertificate")
	var certificate: String = "---BEGIN---"
}
```

사용 지점 타깃을 지정할 때 지원하는 타깃 목록

- property : 프로퍼티 전체 (자바에서 선언된 어노테이션에는 이 지점 타깃 지정 x)
- field: 프로퍼티에 의해 생성되는 필드
- get: 프로퍼티 게터
- set: 프로퍼티 세터
- receiver: 확장 함수나 프로퍼티의 수신 객체 파라미터
- param: 생성자 파라미터
- setparam 세터 파라미터
- delegate: 위임 프로퍼티의 위임 인스턴스를 담아둔 필드
- file: 파일 안에 선언된 최상위 함수와 프로퍼티를 담아두는 클래스

<aside>
💡

자바 API를 어노테이션으로 제어하기

코틀린 선언을 자바에 노출하는 방법을 제어하기 위한 어노테이션들이 있다.

@Volatile 은 자바의 volatile 키워드를 그대로 대신한다.

@JvmName 은 코틀린 선언이 만들어내는 자바 필드나 메서드 이름을 변경한다

@JvmStatic 은 자바 정적 메서드로 노출된다

@JvmOverloads 는 디폴트 파라미터 값이 오버로딩 함수를 생성해준다.

@JvmField  게터나 세터가 없는 자바 필드로 노출시킨다

@JvmRecord data class를 자바의 레코드 클래스로 선언한다

## 12.1.3 어노테이션을 활용해 JSON 직렬화 제어

자바 직렬화 라이브러리로 잭슨, 지슨이 대표적이다.

제이키드는 코틀린 직렬화 라이브러리이다.

직렬화는 serialize(str)

역직렬화는 deserialize<Person>(json) 을 사용한다

기본적으로 모든 프로퍼티를 직렬화하며 프로퍼티 이름을 키로 사용한다.

@JsonExclude, @JsonName 이라는 어노테이션을 다룬다.

이 어노테이션 들이 어떻게 프로퍼티를 exclude(제외)하고 rename(키 이름 변경) 하는 것일까?

## 12.1.4 어노테이션 선언

어노테이션을 선언하려면 일반 클래스 앞에 annotation 변경자만 붙이면 된다.

```kotlin
annotation class JsonExclude
```

파라미터가 있다면 주 생성자에 val로 선언해야 한다

```kotlin
annotation class JsonName(val name: String)
```

자바의 경우는?

```java
public @interface JsonName {
	String value(); // 필수 메서드 <-> 반면 코틀린은 name을 갖음
}
```

## 12.1.5 메타어노테잇션: 어노테이션을 처리하는 방법 제어

코틀린 어노테이션 클래스에도 어노테이션을 붙일 수 있다. 이러한 어노테이션을 메타어노테이션(meta-annotation)이라 부른다.

표준 라이브러리나 프레임워크 들은 여러 메타어노테이션을 제공하며 컴파일러가 어노테이션을 처리하는 방법을 제어한다.

@Target 이 가장 대표적인 표준 라이브러리 어노테이션이다. 바로 적용 가능한 타겟을 지정하기 위한 어노테이션이다.

```kotlin
@Target(AnnotationTarget.CLASS, AnnotationTarget.Method)
annotation class BindingAnnotation
```

AnnotationTarget.PROPERTY는 Java에서는 사용할 수 없다. 사용하려면 AnnotationTarget.FIELD를 추가로 넣어야 한다.

@Retention 어노테이션은 정의 중인 어노테이션 클래스를 소수 수준에서만 유지할지, .class 파일에 저장할지, 실행 시점에 리플렉션을 사용해 접근할 수 있게 할지를 지정하는 메타어노테이션이다.

대부분 어노테이션은 런타임에 적용할 수 있다. 코틀린에서는 자바와 달리 @Retention을 디폴트로 RUNTIME으로 지정하였다.

## 12.1.6 어노테이션 파라미터로 클래스 사용

어떤 클래스를 선언 메타데이터로 참조할 수 있는 기능이 필요하다면

Class::class 를 넣어주어야 한다. 

클래스 이름 + ::class

타입은 Java에서는 Clazz이다.

Kotlin에서는 KClass이다.

```kotlin
data clss Person(
	val name: String,
	@DeserializeInterface(CompanyImpl::class) val company: Company
)
```

@DeserializeInterface 스펙이 KClass<out Any>를 받기 때문에 out즉 자식관계인 CompanyImpl을 받을 수 있다.

## 12.1.7 어노테이션 파라미터로 제너릭 클래스 받기

기본적으로 제이키드는 기본 타입(primitive, refer)가 아닌 프로퍼티를 내포된 객체로 직렬화 한다.

만약 기본타입이 아닌경우는? 커스텀 역직렬화를 구현할 수 있다.

@CustomSerializer

```kotlin
annotation class CustomSerializer(
	val serializerClass: KClass<out ValueSerializer<*>> 
						// star projection을 사용하여 어떤 타입이든 들어올 수 있다고 표시
)

@CustomSerializer(ValueSerializeImpl::class)

interface ValueSerialize<T> {
	fun toJsonValue(value: T): Any?
	fun fromJsonValue(jsonValue: Any?): T
}
```

근데 toJsonValue에서 T에 저장된 필드들에는 어떻게 접근하고 fromJsonValue에서는 어떤 필드들이 있는지 알 수 있을까?

## 12.2 리플렉션: 실행 시점에 코틀린 객체 내부 관찰

리플렉션은 실행시점에 객체 혹은 클래스의 정보를 동적으로 확인하는 기능이다.

## 12.2.1 코틀린 리플렉션 API: KClass, KCllable, KFunction, KProperty

- KClass : 클래스 안에 모든 선언을 열거하고 클래스의 상위 클래스를 얻는 등의 작업이 가능하다. 
MyClass::class 이런식으로 얻을 수 있다, 마찬가지로 myObject 객체의 클래스를 실행시점에 얻으려면 myObject::class를 사용하면 된다.
    - .memberProperties : 클래스와 모든 조상 클래스 내부에 정의된 비확장 프로퍼티를 가져온다.
    - simpleName, qualifiedName : 클래스 이름을 나타내지만 익명 클래스인 경우 null 이다
    - KCallable : 함수나 프로퍼티를 아우르는 공통 인터페이스. call 메서드를 통해 함수나 프로퍼티를 가져올 수 있다.
        - 인자로 varargs 리스트를 전달
    - KFunction : 함수를 수행하기 위한 메서드 (타입 포함)
        - KFunction1<Int, Unit> ..등 이런식
        - invoke, call 메서드 사용
    - KProperty : 프로퍼티를 호출
        - call : 게터를 호출
        - [setter.call](http://setter.call) : 세터를 호출
