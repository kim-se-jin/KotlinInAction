### Q1) 책에서 DSL의 대표적인 예시로 SQL과 정규식을 들었는데요. SQL을 내부 DSL로 쓰는건 라이브러리를 보여줬는데, 왜 정규식을 코틀린 내부 DSL로 사용하는 예시는 들지 않았을까요?

**A) 김세진**

- 정규식이 내부 DSL로 만들기에 까다로운 형태이기 때문.
    - SQL은 키워드(`SELECT`, `FROM`, `WHERE`)와 식별자(테이블명, 컬럼명)가 명확히 분리된 구조.
    - 정규식은 문법이 기호 중심에 이미 충분히 압축된 DSL이라, 내부 DSL사용 시 글자수가 휠씬 늘어남.
    - 원본 문법이 더 짧고 익숙하면 굳이 내부 DSL로 안만들어도 됨.
    - 잘못된 정규식은 컴파일 시점에 보통 못잡기 때문에, 컴파일 시점 검증의 이득이 크지 않음.

### Q1) 일반 API와 DSL을 구분 짓는 가장 핵심적인 차이는 무엇일까요?

**A) 김세진**

- 일반 API: 명령형. "이것을 한다, 다음에 저것을 한다”
    - 평면적인 호출의 나열. 호출 순서로 의미를 표현.
    - 같은 객체에 반복해서 메서드를 호출할 때 매번 변수명을 명시해야 함.
    - 가독성 좋음

- DSL: 선언적. "전체 구조는 이렇다"
    - 코드 구조 자체가 도메인 구조를 반영. 람다 중첩, 메서드 체이닝, 수신 객체 지정 람다로 계층을 만듦.
    - 수신 객체 지정 람다로 컨텍스트를 자동 전달하기 때문에 반복이 사라짐.
    - 가독성 안좋음
