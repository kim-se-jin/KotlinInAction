### Q2) 다른 동시성 처리 방법과 비교했을 때 코루틴이 갖는 장점/단점이 무엇인가요? (p.624)

**A) 김세진**

- 스레드와 비교
- 스레드는 OS 수준의 동시성 단위. JVM에서 스레드 하나는 운영체제 스레드 하나에 대응 (1:1 매핑).

**비용 차이**

- 스레드 — 생성 비용 큼. 컨텍스트 스위칭 비용 큼. 스택 메모리 1MB 정도. JVM에서 수천 개 만들면 메모리 부족
- 코루틴 — 생성 비용 거의 없음. 메모리는 객체 크기 정도(수백 바이트). 수십만 개 동시 실행 가능
1. **경량성**. 스레드 대비 메모리/생성 비용 압도적으로 적음
2. **동기 코드와 같은 작성 방식**. 콜백 지옥 없이 위에서 아래로 흐름
3. **구조화된 동시성**. 부모-자식 관계로 취소/예외 전파 자동화
4. **표준 예외 처리**. `try-catch` 그대로 사용
5. **컨텍스트 전환의 명시성**. `withContext(Dispatchers.IO)` 식으로 어디서 실행할지 명확히 표현

### Q1) 코루틴의 실행 기록은 JVM 메모리 중 어느 영역에 저장되고 있을까요?

**A) 김세진**

- 힙(Heap)에 저장. 정확히는 연속 객체(continuation object) 형태로.
- suspend 함수는 컴파일 시점에 **상태 머신(state machine)**으로 변환됨. 각 중단 지점(suspend 호출, delay, await 등)이 상태 머신의 한 상태가 됨.
- `suspend` 함수는 컴파일 시점에 **상태 머신(state machine)**으로 변환됨. 각 중단 지점(`suspend` 호출, `delay`, `await` 등)이 상태 머신의 한 상태가 됨.

```kotlin
suspend fun example() {
    val a = stepA()      // 중단 가능
    val b = stepB(a)     // 중단 가능
    println(b)
}
```

컴파일 후 대략 이런 구조.

```kotlin
fun example(continuation: Continuation<*>) {
    val state = continuation as ExampleStateMachine
    when (state.label) {
        0 -> {
            state.label = 1
            val result = stepA(state)
            if (result == COROUTINE_SUSPENDED) return
            state.a = result
            // 계속 진행
        }
        1 -> {
            state.label = 2
            val result = stepB(state.a, state)
            if (result == COROUTINE_SUSPENDED) return
            state.b = result
        }
        2 -> {
            println(state.b)
        }
    }
}
```

`ExampleStateMachine` 객체가 코루틴의 실행 기록. 다음 정보를 담음.

- 현재 어디까지 실행됐는지 (`label`)
- 지역 변수 값 (`a`, `b` 등)
- 자기 자신을 호출한 상위 continuation 참조

이 객체가 **힙에 할당**됨. 일반 객체와 동일.

JVM의 힙은 더 세분화됨. 코루틴 객체는 일반 객체와 마찬가지로.

- 신생 객체 — Young Generation (Eden, Survivor)
- 오래 살아남는 객체 — Old Generation으로 승격

짧게 끝나는 코루틴은 Eden에서 회수. 오래 실행되는 코루틴은 Old Generation으로 갈 수 있음.

### Q2) Dispatcher를 커스텀하게 사용할 경우가 있을까요?

**A) 김규**

- 디스패처가 하는 일이 코루틴이 어느 스레드에 들어갈 것인지 관리하는 것
- 가장 특수한 경우는 Dispatchers.Main 이 커버하고 있다고 생각합니다
- 특정 작업을 반드시 특정 스레드풀에서만 실행하여, 다른 작업들에 영향을 주고 싶지 않다면 사용할 수 있을 것 같음 (`newFixedThreadPool`)
