# 15장. 구조화된 동시성

---

## 15.1 코루틴 스코프가 코루틴 간의 구조를 확립한다

- 코루틴은 단순히 비동기 코드를 실행하는 수단이 아니라, **부모-자식 관계**로 이루어진 계층 구조 안에서 동작
    - 이 계층 구조를 가능하게 하는 매커니즘: **코루틴 스코프(CoroutineScope)**

- 구조화된 동시성(Structured Concurrency)
    - 코루틴은 반드시 특정 스코프 안에서 시작된다.
    - 부모 코루틴은 모든 자식 코루틴이 완료되기 전까지 완료되지 않는다.
    - 자식 코루틴의 실패나 취소는 부모 및 형제 코루틴에 전파될 수 있다.

---

### 15.1.1 코루틴 스코프 생성: coroutineScope 함수

`coroutineScope`는 새로운 스코프를 만들고 그 안에서 자식 코루틴들을 실행하는 **일시 중단 함수**
- 모든 자식이 완료되어야 `coroutineScope` 블록이 반환됨.


```kotlin
suspend fun loadData() = coroutineScope {
    val a = async { fetchFromNetworkA() }
    val b = async { fetchFromNetworkB() }
    a.await() + b.await()
}
```


- `coroutineScope`는 **호출한 코루틴의 콘텍스트를 상속**받는다.
- 자식 중 하나가 예외를 던지면 나머지 자식도 취소되고 예외가 전파된다.
- `runBlocking`과 달리 스레드를 블로킹하지 않는다.
- `supervisorScope`와의 차이점: `coroutineScope`는 자식 하나의 실패가 전체를 취소하지만, `supervisorScope`는 각 자식이 독립적으로 실패를 처리한다.

---

### 15.1.2 코루틴 스코프를 컴포넌트와 연관시키기: CoroutineScope

장기적으로 살아있는 컴포넌트(예: Android의 ViewModel, 서버의 서비스 객체)는 CoroutineScope 인터페이스를 직접 구현하거나 위임하여 코루틴을 관리함

- `Job` 또는 `SupervisorJob`을 콘텍스트에 포함시켜야 스코프 전체를 취소할 수 있다.
- 컴포넌트의 생명주기가 끝날 때 반드시 `scope.cancel()`을 호출해야 한다. 그렇지 않으면 코루틴이 계속 실행되며 메모리 누수나 불필요한 작업이 발생한다.
- Android에서는 `viewModelScope`, `lifecycleScope` 등의 확장 프로퍼티가 이 패턴을 자동으로 처리해준다.

```kotlin
class MyViewModel : ViewModel() {
    private val scope = CoroutineScope(Dispatchers.Main + SupervisorJob())

    fun loadUser() {
        scope.launch {
            val user = fetchUser()
            updateUI(user)
        }
    }

    fun onDestroy() {
        scope.cancel()
    }
}
```

### 15.1.3 GlobalScope의 위험성

`GlobalScope`는 어떤 구조화된 스코프에도 속하지 않는 **전역 스코프**다. 앱의 전체 생명주기 동안 존재

```kotlin
// 권장하지 않는 코드
GlobalScope.launch {
    delay(1000)
    println("전역 코루틴 실행")
}
```

`GlobalScope`의 문제점
- 부모-자식 관계가 없으므로 구조화된 동시성의 보장을 받지 못한다.
- 호출한 코루틴이 취소되어도 `GlobalScope`의 코루틴은 계속 실행된다.
- 테스트가 어렵다. 테스트 종료 후에도 코루틴이 살아있을 수 있다.
- 예외 처리가 명시적이지 않으면 조용히 무시된다.

그럼에도 `GlobalScope`가 정당하게 사용되는 경우는 앱 전체 수명 동안 실행되어야 하는 소수의 최상위 작업(예: 로그 전송, 주기적 동기화)에 한정되며, 이 경우에도 신중하게 사용해야 함

---

### 15.1.4 코루틴 콘텍스트와 구조화된 동시성

`CoroutineContext`: 코루틴의 실행 환경을 정의하는 요소들의 집합

| 요소 | 역할 |
|---|---|
| `Job` | 코루틴의 생명주기 관리, 취소 전파 |
| `CoroutineDispatcher` | 실행 스레드 결정 (`Dispatchers.Main`, `IO`, `Default`) |
| `CoroutineName` | 디버깅용 이름 |
| `CoroutineExceptionHandler` | 미처리 예외 처리 |

자식 코루틴은 부모 코루틴의 콘텍스트를 상속받는다. 단, `Job`은 예외적으로 **새로운 Job 인스턴스가 생성**되어 부모 Job의 자식이 된다. 이것이 구조화된 동시성의 계층 관계가 만들어지는 메커니즘이다.

```kotlin
val parentJob = CoroutineScope(Dispatchers.Default).launch {
    // 이 launch의 Job이 부모 Job
    launch {
        // 이 launch의 Job은 부모 Job의 자식
    }
}
```

콘텍스트를 명시적으로 오버라이드할 수 있다.

```kotlin
launch(Dispatchers.IO) {
    // 부모의 Dispatcher만 IO로 교체하고 나머지는 상속
}
```

## 15.2 취소

### 15.2.1 취소 촉발

코루틴을 취소하려면 `Job.cancel()`을 호출한다.

```kotlin
val job = scope.launch {
    repeat(1000) { i ->
        println("작업 $i 수행 중")
        delay(500)
    }
}

delay(1300)
job.cancel()
job.join() // 취소가 완전히 완료될 때까지 대기
```

- `cancel()`은 즉각적인 종료를 보장하지 않는다.
- 코루틴이 다음 취소 가능 지점에 도달했을 때 취소된다.
- `cancel()` 후 `join()`을 함께 사용하는 패턴이 일반적이며, 이를 줄여서 `cancelAndJoin()`으로 쓸 수 있다.

---

### 15.2.2 시간제한이 초과된 후 자동으로 취소 호출

`withTimeout`과 `withTimeoutOrNull`은 지정한 시간 안에 작업이 완료되지 않으면 자동으로 취소한다.

```kotlin
// 시간 초과 시 TimeoutCancellationException 발생
val result = withTimeout(1000L) {
    delay(2000L)
    "완료"
}

// 시간 초과 시 null 반환
val result = withTimeoutOrNull(1000L) {
    delay(2000L)
    "완료"
} // result == null
```

- `withTimeout`은 `TimeoutCancellationException`을 던지는데, 이는 `CancellationException`의 하위 클래스
  -  `withTimeoutOrNull`은 예외 대신 `null`을 반환하므로 더 안전한 경우가 많다.

---

### 15.2.3 취소는 모든 자식 코루틴에게 전파된다

부모 코루틴이 취소되면 그 자식 코루틴도 모두 취소된다. 이 전파는 재귀적으로 이루어진다.

```kotlin
val parent = scope.launch {
    val child1 = launch {
        delay(Long.MAX_VALUE)
        println("자식1 완료") // 실행되지 않음
    }
    val child2 = launch {
        delay(Long.MAX_VALUE)
        println("자식2 완료") // 실행되지 않음
    }
    delay(Long.MAX_VALUE)
}

delay(100)
parent.cancel() // child1, child2 모두 취소됨
```

취소는 **위에서 아래로**만 전파된다.
예외는 자식에서 부모 방향으로 전파되지만, 취소는 부모에서 자식 방향으로 전파된다.

---

### 15.2.4 취소된 코루틴은 특별한 지점에서 CancellationException을 던진다

취소는 내부적으로 `CancellationException`을 통해 구현된다. 코루틴이 일시 중단 지점(`delay`, `yield`, `await` 등)에 도달하면 취소 여부를 확인하고, 취소 요청이 있으면 `CancellationException`을 던진다.

```kotlin
val job = scope.launch {
    try {
        delay(1000)
    } catch (e: CancellationException) {
        println("취소됨: ${e.message}")
        throw e // 반드시 재던져야 함
    } finally {
        println("정리 작업") // 취소 후에도 실행됨
    }
}
```

- `CancellationException`을 `catch`로 잡았다면 반드시 다시 `throw`해야 한다.
- `finally` 블록은 취소된 경우에도 실행되므로 리소스 해제 코드 작성

---

### 15.2.5 취소는 협력적이다

코루틴의 취소는 강제 종료가 아니라 **협력적(cooperative)** 이다. 일시 중단 함수(`delay`, `yield`, `withContext` 등)는 자동으로 취소 지점이 된다. 반면 CPU 집약적이거나 일시 중단 지점이 없는 코드는 취소가 즉시 반영되지 않는다.

```kotlin
// 문제 있는 코드: 취소가 동작하지 않음
val job = scope.launch(Dispatchers.Default) {
    var i = 0
    while (i < 1_000_000) {
        i++ // 일시 중단 지점 없음 -> 취소 불가
    }
}
```

해결 방법
1. `isActive` 프로퍼티로 취소 여부를 직접 확인한다.
2. `yield()`를 주기적으로 호출하여 취소 지점을 만든다.

---

### 15.2.6 코루틴이 취소됐는지 확인

`isActive` 프로퍼티를 사용하면 현재 코루틴의 취소 여부를 명시적으로 확인할 수 있다.

```kotlin
val job = scope.launch(Dispatchers.Default) {
    var i = 0
    while (isActive && i < 1_000_000) {
        i++
    }
}
```

`ensureActive()`를 사용하면 취소 상태일 때 `CancellationException`을 즉시 던진다.

```kotlin
while (i < 1_000_000) {
    ensureActive()
    i++
}
```

---

### 15.2.7 다른 코루틴에게 기회를 주기: yield 함수

`yield()`는 현재 코루틴의 실행을 일시 중단하고 다른 코루틴이 실행될 수 있는 기회를 제공하는 일시 중단 함수다.

```kotlin
val job = scope.launch(Dispatchers.Default) {
    var i = 0
    while (i < 1_000_000) {
        i++
        if (i % 10_000 == 0) yield()
    }
}
```

`yield()`가 하는 일

1. 현재 코루틴이 취소 상태인지 확인하고, 취소되었다면 `CancellationException`을 던진다.
2. 동일한 디스패처에서 대기 중인 다른 코루틴에게 실행 기회를 준다.

---

### 15.2.8 리소스를 얻을 때 취소를 염두에 두기

코루틴이 취소되더라도 리소스는 반드시 해제되어야 한다. `try-finally` 패턴을 사용한다.

```kotlin
val job = scope.launch {
    val resource = acquireResource()
    try {
        useResource(resource)
    } finally {
        resource.release()
    }
}
```

`finally` 안에서 일시 중단 함수가 필요한 경우 `withContext(NonCancellable)`을 사용한다.

```kotlin
finally {
    withContext(NonCancellable) {
        delay(100)
        resource.release()
    }
}
```

`NonCancellable`은 반드시 실행되어야 하는 정리 코드에만 한정적으로 사용해야 한다.

### 15.2.9 프레임워크가 대신 취소를 할 수 있다

Android에서 프레임워크 제공 스코프를 활용하면 취소 관리를 자동화할 수 있다.

| 스코프 | 자동 취소 시점 |
|---|---|
| `viewModelScope` | ViewModel cleared 시 |
| `lifecycleScope` | Activity / Fragment 파괴 시 |
| `repeatOnLifecycle` | 지정한 생명주기 상태에 따라 자동 시작/취소 |

```kotlin
class MyActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.uiState.collect { state ->
                    updateUI(state)
                }
            }
        }
    }
}
```
