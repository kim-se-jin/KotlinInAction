# 16장. 플로우

---

## 16.1 플로우는 연속적인 값의 스트림을 모델링한다

### 16.1.1 플로우를 사용하면 배출되자마자 원소를 처리할 수 있다

`Sequence`나 `List`는 모든 원소가 준비된 후에 소비한다. 반면 `Flow`는 값이 생성(배출)되는 즉시 소비자가 처리할 수 있다.

장점
- 모든 데이터가 준비될 때까지 기다릴 필요가 없다.
- 메모리에 전체 데이터를 올려두지 않아도 된다.
- 생산자와 소비자가 독립적인 속도로 동작할 수 있다.

```kotlin
fun getTemperatures(): Flow<Double> = flow {
    while (true) {
        emit(readSensor()) // 값이 생성될 때마다 즉시 배출
        delay(1000)
    }
}

suspend fun main() {
    getTemperatures().collect { temperature ->
        println("현재 온도: $temperature") // 배출되자마자 처리
    }
}
```

---

### 16.1.2 코틀린 플로우의 여러 유형

- 콜드 플로우(Cold Flow)는 수집자(`collect`)가 있을 때만 실행된다. 각 수집자마다 독립적인 실행 흐름을 가지며, `flow { }` 빌더로 생성한다. API 요청, 파일 읽기처럼 요청 시마다 새로 실행되어야 하는 작업에 적합

- 핫 플로우(Hot Flow)는 수집자와 무관하게 독립적으로 실행된다. 여러 수집자가 동일한 스트림을 공유하며, `SharedFlow`와 `StateFlow`가 이에 해당한다. UI 이벤트, 센서 데이터, 앱 상태처럼 공유가 필요한 데이터에 적합

## 16.2 콜드 플로우

콜드 플로우는 구독자가 수집을 시작할 때 비로소 데이터 생성이 시작되는 플로우다.

---

### 16.2.1 flow 빌더 함수를 사용해 콜드 플로우 생성

`flow { }` 빌더는 콜드 플로우를 만드는 가장 기본적인 방법
블록 안에서 `emit()`을 호출하여 값을 배출한다.

```kotlin
val numbersFlow: Flow<Int> = flow {
    println("플로우 시작")
    for (i in 1..5) {
        delay(100)
        emit(i) // 값 배출
    }
}
```

`emit()`은 일시 중단 함수이므로 `flow { }` 블록 안에서만 호출할 수 있다. 블록 안에서는 다른 일시 중단 함수도 자유롭게 호출할 수 있다. `flowOf()`와 `asFlow()`도 간단한 플로우 생성에 사용된다.

```kotlin
val flow1 = flowOf(1, 2, 3)
val flow2 = listOf("a", "b", "c").asFlow()
```

---

### 16.2.2 콜드 플로우는 수집되기 전까지 작업을 수행하지 않는다

- `flow { }` 블록의 코드는 `collect()`가 호출되기 전까지 단 한 줄도 실행되지 않는다.


- 각 수집자는 독립적인 실행 흐름을 갖는다. 동일한 플로우를 두 번 수집해도 각각 독립적으로 실행되므로 다른 값이 나올 수 있다.

```kotlin
val flow = flow {
    emit(Random.nextInt())
}

flow.collect { println(it) } // 예: 42
flow.collect { println(it) } // 예: 7 (다른 값)
```

---

### 16.2.3 플로우 수집 취소

플로우 수집은 코루틴 취소 메커니즘과 통합되어 있다. 수집 중인 코루틴이 취소되면 플로우 수집도 함께 취소된다.

```kotlin
val job = scope.launch {
    flow {
        repeat(10) {
            emit(it)
            delay(100)
        }
    }.collect { value ->
        println("수집: $value")
    }
}

delay(350)
job.cancel() // 수집 중단
```

`collect()`는 일시 중단 함수이므로, 코루틴이 취소되면 다음 `emit()` 또는 `delay()` 지점에서 `CancellationException`이 발생하고 수집이 종료된다. `withTimeoutOrNull`과 함께 사용하면 시간제한 수집도 가능하다.

```kotlin
withTimeoutOrNull(500) {
    infiniteFlow.collect { println(it) }
}
```

---

### 16.2.4 콜드 플로우의 내부 구현

- `flow { }` 빌더로 생성된 플로우는 내부적으로 `collect()`가 호출될 때 블록을 실행하고, 블록 안의 `emit()`이 `FlowCollector.emit()`을 호출하는 구조
  - 추가적인 스레드나 코루틴 없이 호출한 코루틴의 콘텍스트에서 그대로 실행됨

```kotlin
// flow 빌더의 의사 코드
fun <T> flow(block: suspend FlowCollector<T>.() -> Unit): Flow<T> {
    return object : Flow<T> {
        override suspend fun collect(collector: FlowCollector<T>) {
            collector.block() // collect 호출 시점에 블록 실행
        }
    }
}
```

```kotlin
listOf(1, 2, 3).asFlow()
    .map { it * 2 }    // 새 Flow 반환
    .filter { it > 2 } // 새 Flow 반환
    .collect { println(it) } // 이 시점에 전체 체인 실행
```

---

### 16.2.5 채널 플로우를 사용한 동시성 플로우

- 기본 `flow { }` 빌더는 단일 코루틴에서 순차적으로 실행됨
- 병렬로 값을 생성해야 하는 경우 `channelFlow { }`를 사용한다.

```kotlin
val flow = channelFlow {
    launch {
        send(fetchFromSourceA()) // 병렬 실행
    }
    launch {
        send(fetchFromSourceB()) // 병렬 실행
    }
}
```

## 16.3 핫 플로우

핫 플로우는 수집자와 무관하게 독립적으로 값을 배출하는 플로우다.

---

### 16.3.1 공유 플로우는 값을 구독자에게 브로드캐스트한다

- `SharedFlow`는 여러 구독자에게 동일한 값을 동시에 브로드캐스트하는 핫 플로우
  - `MutableSharedFlow`로 생성하고 `emit()`으로 값을 배출한다.

```kotlin
val sharedFlow = MutableSharedFlow<String>()

scope.launch {
    sharedFlow.collect { println("구독자1: $it") }
}

scope.launch {
    sharedFlow.collect { println("구독자2: $it") }
}

sharedFlow.emit("이벤트A") // 두 구독자 모두 수신
```

`SharedFlow`의 주요 파라미터는 다음과 같다.

```kotlin
MutableSharedFlow<T>(
    replay = 0,              // 새 구독자에게 이전 값을 몇 개까지 재전송할지
    extraBufferCapacity = 0, // 추가 버퍼 크기
    onBufferOverflow = BufferOverflow.SUSPEND // 버퍼 초과 시 동작
)
```

`replay` 값이 0이면 새로 구독한 수집자는 구독 이후에 배출된 값만 받는다. `replay = 1`이면 새 구독자도 마지막으로 배출된 값을 즉시 받는다. `SharedFlow`는 완료 상태가 없어 명시적으로 닫을 수 없으며, 스코프가 취소될 때까지 계속 활성 상태다.

---

### 16.3.2 시스템 상태 추적: 상태 플로우

`StateFlow`는 현재 상태를 보유하고 상태가 변경될 때마다 구독자에게 알리는 특수한 핫 플로우다. 항상 초기값이 있으며, 현재 값을 `value` 프로퍼티로 즉시 읽을 수 있다.

```kotlin
val stateFlow = MutableStateFlow(0) // 초기값 0

scope.launch {
    stateFlow.collect { println("상태: $it") }
}

stateFlow.value = 1
stateFlow.value = 2
// 출력:
// 상태: 0 (초기값)
// 상태: 1
// 상태: 2
```

`StateFlow`의 핵심 특성은 다음과 같다. 항상 현재 값을 보유하며 `stateFlow.value`로 즉시 접근 가능하다. 새 구독자는 즉시 현재 값을 받는다. 동일한 값을 연속으로 설정하면 배출하지 않는다.

```kotlin
stateFlow.value = 5
stateFlow.value = 5 // 동일한 값 → 배출 안 됨
stateFlow.value = 6 // 다른 값 → 배출됨
```

Android에서 ViewModel의 UI 상태 관리에 주로 사용된다. 외부에는 읽기 전용 `StateFlow`로 노출하고, 내부에서만 `MutableStateFlow`로 상태를 변경하는 패턴이 일반적이다.

```kotlin
class MyViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(UiState.Loading)
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()

    fun loadData() {
        viewModelScope.launch {
            _uiState.value = UiState.Loading
            val data = repository.fetchData()
            _uiState.value = UiState.Success(data)
        }
    }
}
```

---

### 16.3.3 상태 플로우와 공유 플로우의 비교

`SharedFlow`는 초기값이 없고 현재 값에 직접 접근할 수 없다. 새 구독자에게는 `replay` 설정에 따라 이전 값을 전달하며, 동일한 값도 항상 배출한다. 이벤트 브로드캐스트에 적합하다.

`StateFlow`는 초기값이 필수이며 `value` 프로퍼티로 현재 값에 즉시 접근할 수 있다. 새 구독자에게는 항상 현재 값을 전달하고, 동일한 값은 배출하지 않는다. 상태 관리에 적합하다.

`StateFlow`는 `replay = 1`이고 동일 값 중복 배출이 없는 `SharedFlow`의 특수한 형태로 볼 수 있다.

---

### 16.3.4 핫 플로우, 콜드 플로우, 공유 플로우, 상태 플로우: 언제 어떤 플로우를 사용할까?

콜드 플로우(`flow { }`)는 각 수집자마다 독립적인 데이터 흐름이 필요할 때 사용한다. 네트워크 요청, 데이터베이스 쿼리처럼 요청 시마다 새로 실행되어야 하는 작업, 수집자가 없을 때 불필요한 작업을 하고 싶지 않을 때 적합하다.

```kotlin
fun fetchUser(id: String): Flow<User> = flow {
    emit(api.getUser(id))
}
```

공유 플로우(`SharedFlow`)는 여러 구독자에게 동일한 이벤트를 브로드캐스트할 때 사용한다. 클릭 이벤트, 네비게이션 명령, 토스트 메시지처럼 이벤트가 한 번 발생하고 사라지는 특성이 있을 때 적합하다.

```kotlin
private val _events = MutableSharedFlow<UiEvent>()
val events: SharedFlow<UiEvent> = _events.asSharedFlow()
```

상태 플로우(`StateFlow`)는 현재 상태를 지속적으로 보유하고 변화를 관찰할 때 사용한다. UI 상태처럼 항상 현재 값이 있어야 하고, 새 구독자가 즉시 현재 상태를 알아야 하는 경우에 적합하다.

```kotlin
private val _uiState = MutableStateFlow<UiState>(UiState.Initial)
val uiState: StateFlow<UiState> = _uiState
```

채널 플로우(`channelFlow { }`)는 콜드 플로우이지만 내부에서 여러 코루틴이 병렬로 값을 생성해야 할 때 사용한다.
