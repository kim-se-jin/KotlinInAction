
# 16장 — 플로우 (Flow)


코루틴(`suspend` 함수)은 **값 하나**를 비동기적으로 돌려준다.
하지만 현실에는 **여러 개의 값이 시간 차를 두고 들어오는** 상황이 많다.

- 센서가 1초마다 측정값을 보내온다
- 서버가 데이터를 페이지 단위로 조금씩 내려준다
- 사용자가 검색창에 글자를 한 자씩 입력한다

이렇게 **시간에 따라 연속적으로 흘러나오는 값들**을 다루는 코틀린의 도구가 **플로우(Flow)** 다.

---

## 16.1 플로우는 연속적인 값의 스트림을 모델링한다

### 16.1.1 플로우를 사용하면 배출되자마자 원소를 처리할 수 있다

값을 여러 개 돌려주고 싶을 때 가장 쉽게 떠올리는 방법은 **리스트를 반환**하는 것이다.

```kotlin
suspend fun createValues(): List<Int> {
    return buildList {
        add(1)
        delay(1000)
        add(2)
        delay(1000)
        add(3)
    }
}
```

문제: 이 함수는 **모든 값이 다 준비될 때까지(2초)** 기다린 뒤에야 리스트를 통째로 돌려준다.
즉, 첫 번째 값 `1`은 이미 0초에 만들어졌는데도 호출자는 2초를 기다려야 한다.

플로우를 쓰면 값이 **배출(emit)되는 즉시 하나씩** 처리할 수 있다.

```kotlin
fun createValues(): Flow<Int> = flow {
    emit(1)        // 0초: 바로 흘려보냄
    delay(1000)
    emit(2)        // 1초
    delay(1000)
    emit(3)        // 2초
}
```

- `emit(x)` : 플로우 안에서 값 하나를 "배출(흘려보냄)"한다
- 수집하는 쪽은 값이 나올 때마다 즉시 처리한다 → **기다리는 시간이 사라진다**


### 16.1.2 코틀린 플로우의 여러 유형

플로우의 핵심은 단 두 가지 개념이다.

- **배출(emit)**: 생산자(producer)가 값을 흘려보낸다
- **수집(collect)**: 소비자(consumer)가 값을 받아 처리한다

```kotlin
interface Flow<out T> {
    suspend fun collect(collector: FlowCollector<T>)
}
```

`collect`는 `suspend` 함수다. 즉 **수집은 코루틴 안에서만** 할 수 있고, 값을 기다리는 동안 스레드를 막지 않는다.

코틀린 플로우는 크게 두 종류로 나뉜다.

| 구분 | 콜드 플로우 (Cold Flow) | 핫 플로우 (Hot Flow) |
|------|----------------------|---------------------|
| 동작 시점 | **수집(collect)해야** 시작 | 수집과 무관하게 **이미 흐르고 있음** |
| 구독자 | 수집할 때마다 처음부터 새로 실행 | 여러 구독자가 **같은 흐름을 공유** |
| 비유 | 주문 시 굽는 피자 | 라디오 방송 (틀면 지금 나오는 것부터) |
| 대표 타입 | `Flow` (`flow {}` 빌더) | `SharedFlow`, `StateFlow` |

## 16.2 콜드 플로우 (Cold Flow)

### 16.2.1 flow 빌더 함수를 사용해 콜드 플로우 생성

```kotlin
fun letters(): Flow<String> = flow {
    log("플로우 시작")
    emit("A")
    delay(500)
    emit("B")
}
```

- `flow { }` 블록 안은 `suspend` 컨텍스트라 `delay` 같은 일시 중단 함수를 자유롭게 쓸 수 있다
- `emit()`으로 값을 내보낸다
- 수집은 `.collect { }` 로 한다

```kotlin
fun main() = runBlocking {
    letters().collect { value ->
        log("받음: $value")
    }
}
```


### 16.2.2 콜드 플로우는 수집되기 전까지 작업을 수행하지 않는다

이게 "콜드(차갑다)"라는 이름의 이유다.

```kotlin
val flow = letters()   // 이 시점에는 "플로우 시작" 로그조차 찍히지 않는다!
// ...
flow.collect { ... }   // collect를 호출하는 순간 비로소 flow{} 블록이 실행된다
```

- 플로우를 **변수에 담아두기만 하면** 아무 일도 일어나지 않는다
- `collect`(또는 `toList`, `first` 등 **터미널 연산**)를 호출해야 실행된다
- 그래서 **두 번 collect 하면 두 번 처음부터 다시 실행**된다


### 16.2.3 플로우 수집 취소

수집하는 코루틴을 취소하면 플로우도 멈춘다.

```kotlin
withTimeoutOrNull(1300) {     // 1.3초 후 수집 자동 취소
    countingFlow().collect { log("받음: $it") }
}
```

또는 `take(n)` 같은 연산자로 "n개만 받고 끝"을 표현할 수 있다.

> 플로우의 일시 중단 지점(`emit`, `delay`)은 모두 **취소 가능 지점**이다. 즉 구조적 동시성과 자연스럽게 어울린다.


### 16.2.4 콜드 플로우의 내부 구현

`flow {}`와 `collect {}`는 사실 아주 단순한 함수다. 인터페이스 두 개가 전부다.

```kotlin
interface Flow<out T> {
    suspend fun collect(collector: FlowCollector<T>)
}
interface FlowCollector<in T> {
    suspend fun emit(value: T)
}
```

- `collect`에 넘긴 람다가 곧 `FlowCollector`의 `emit` **구현**이 된다
- `flow {}` 블록에서 `emit(x)`를 호출하면 → 그게 곧 `collect {}`의 람다를 호출하는 것
- 별도의 스레드/채널 없이, **그냥 서로 suspend 함수를 호출하는 관계**일 뿐이다

그래서 콜드 플로우는 기본적으로 **순차적이고 단일 코루틴**에서 돈다.

### 16.2.5 채널 플로우를 사용한 동시성 플로우

`flow {}`는 한 코루틴에서 순차적으로 `emit`해야 한다(다른 코루틴에서 emit 불가).
**여러 코루틴이 동시에 값을 만들어 emit**하고 싶다면 `channelFlow {}`를 쓴다.

```kotlin
fun fetchAll(): Flow<String> = channelFlow {
    launch { send(fetch("A")) }   // 동시에
    launch { send(fetch("B")) }   // 실행되는
    launch { send(fetch("C")) }   // 작업들
}
```

- `channelFlow` 안에서는 `emit` 대신 `send`를 쓴다
- 내부적으로 채널을 통해 값을 모으므로 여러 코루틴에서 안전하게 보낼 수 있다
- 단순 순차 방출이면 `flow {}`가 더 가볍고 빠르다 → **동시성이 필요할 때만** `channelFlow`

## 16.3 핫 플로우 (Hot Flow)

콜드 플로우는 "구독자마다 처음부터 새로 실행"된다.
하지만 **하나의 이벤트 소스를 여러 곳에서 공유**하고 싶을 때가 있다 (예: 클릭 이벤트, 현재 로그인 상태).

이때 쓰는 게 핫 플로우다. 핫 플로우는 **수집자가 있든 없든 독립적으로 존재**하며, 여러 구독자에게 **같은 값을 브로드캐스트**한다.

### 16.3.1 공유 플로우는 값을 구독자에게 브로드캐스트한다

라디오 방송과 같다. 구독(`collect`)을 시작한 시점부터 흘러나오는 값을 받는다. **구독 전에 방출된 값은 (기본적으로) 받지 못한다.**

```kotlin
val messages = MutableSharedFlow<String>()

// 발행 측
scope.launch {
    messages.emit("안녕")
    messages.emit("반가워")
}

// 구독 측 (여러 명이 같은 값을 받음)
scope.launch { messages.collect { log("구독자1: $it") } }
scope.launch { messages.collect { log("구독자2: $it") } }
```

- `MutableSharedFlow` : 값을 직접 `emit`할 수 있는 발행용 타입
- 외부에는 읽기 전용 `SharedFlow`로 노출하는 것이 좋다 (`asSharedFlow()`)
- `replay` 파라미터: 새 구독자에게 **최근 N개**를 다시 보내줄 수 있다


### 16.3.2 시스템 상태 추적: 상태 플로우

`SharedFlow`의 특수한 형태로, **항상 "현재 값" 하나**를 가진다. UI 상태 관리에 가장 많이 쓰인다.

```kotlin
val counter = MutableStateFlow(0)   // 초기값 필수

counter.value = 1                   // .value로 읽기/쓰기
counter.update { it + 1 }           // 원자적 갱신(권장)

counter.collect { log("현재 값: $it") }  // 구독 즉시 "현재 값"부터 받음
```

특징:
- **초기값이 반드시 있어야** 한다
- `.value`로 동기적으로 현재 값을 읽을 수 있다
- 새 구독자는 **구독하자마자 현재 값**을 즉시 받는다 (replay = 1 과 비슷)

**값 기반 합치기(equality-based conflation):**
StateFlow는 새로 설정한 값이 **이전 값과 같으면(`equals`) 방출하지 않는다.**
또 너무 빠르게 값이 바뀌면 중간 값은 건너뛰고 **최신 값만** 전달한다(conflation).


### 16.3.3 상태 플로우와 공유 플로우의 비교

둘 다 핫 플로우지만, **늦게 합류한 구독자가 받는 값**이 결정적으로 다르다.

| | SharedFlow (replay=0) | StateFlow |
|---|---|---|
| 초기값 | 없음 | **필수** |
| 값 보관 | 보관 안 함 (방출하고 흘려보냄) | 항상 **현재 값 하나**를 보관 |
| 늦은 구독자 | 구독 **이후** 값만 받음 (과거 값 못 봄) | 구독 즉시 **현재 값**을 받음 |
| 같은 값 재방출 | 방출함 | **안 함** (conflation) |
| 다루는 것 | "지나간 이벤트" (클릭, 알림) | "현재 상태" (로그인 여부, 카운트) |

```kotlin
// SharedFlow: 1,2 방출 후 합류한 구독자는 3만 본다
// StateFlow : 값이 2까지 바뀐 후 합류한 구독자도 즉시 2를 받고, 이어 3도 받는다
```


> StateFlow는 사실상 `replay=1` + `conflation`이 적용된 SharedFlow의 특수형이라고 보면 된다.

### 16.3.4 핫 플로우, 콜드 플로우, 공유 플로우, 상태 플로우: 언제 어떤 플로우를 사용할까?

**한 줄 결정 가이드**

| 상황 | 선택 |
|------|------|
| 요청 한 번에 값들이 순서대로 흘러나옴 (DB 쿼리, 파일 읽기, 네트워크 스트림) | **콜드 플로우** (`flow {}`) |
| 여러 작업을 동시에 돌려 끝나는 대로 방출 | **`channelFlow {}`** |
| 한 이벤트 소스를 여러 구독자가 공유, "지나간 이벤트"는 놓쳐도 됨 (클릭, 토스트, 알림) | **`SharedFlow`** |
| "현재 상태" 하나를 여러 구독자가 항상 최신으로 봐야 함 (UI 상태, 로그인 여부) | **`StateFlow`** |

**콜드 → 핫 변환 (`shareIn` / `stateIn`)**

비싼 콜드 플로우를 여러 곳에서 구독해야 한다면, 콜드 그대로 두면 구독자마다 처음부터 다시 실행되어 낭비가 생긴다. 핫으로 바꿔 흐름을 공유한다.

```kotlin
val shared: SharedFlow<Int> = coldFlow.shareIn(
    scope = scope,
    started = SharingStarted.WhileSubscribed(),  // 구독자가 있을 때만 동작
    replay = 1
)

val state: StateFlow<Int> = coldFlow.stateIn(
    scope = scope,
    started = SharingStarted.Eagerly,
    initialValue = 0
)
```

`SharingStarted` 옵션:
- `Eagerly` : 즉시 시작, 끝까지 유지
- `Lazily` : 첫 구독자가 생기면 시작, 이후 유지
- `WhileSubscribed()` : 구독자가 있을 때만 동작 (가장 실용적, 리소스 절약)
