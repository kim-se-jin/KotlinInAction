# 정리
- 플로우 연산자의 분류
  - 중간 연산자
    - 코드를 실행하지 않고 변경된 플로우를 반환
  - 최종 연산자
    - 컬렉션, 개별 원소, 계산된 값을 반환하거나 아무 값도 반환하지 않으면서 플로우를 수집하고 실제 코드를 실행
- 중간 연산자
  - 업스트림 플로우에 적용되어 다운스트림 플로우를 반환함
  - 반환된 플로우는 콜드
  - 핫 플로우에 연산자를 적용해도 최종 연산자가 호출되어 핫 플로우를 구독하기 전까지는 실행되지 않음
  - 시퀀스의 `map`, `filter`, `onEach` 사용 가능
  - `transform`
    - 업스트림 플로우의 각 원소에 대해 원하는 만큼의 원소를 다운스트림 플로우에 배출할 수 있음
  - `flowOf`
    - 단순한 값 목록을 배출하는 플로우를 만들 때 사용할 수 있는 줄임 표현
  - `takeWhile`
    - 연산자가 지정한 조건이 더 이상 유효하지 않을 떄 업스트림 플로우를 취소시킴
  - `take`
    - 지정된 개수만 가져오고 플로우를 취소시킴
  - `onCompletion`
    - 플로우가 정상, 취소, 예외로 인해 종료되었을 떄 호출하는 람다를 지정
  - `onStart`
    - 플로우의 수집이 시작될 때 첫 번쨰 배출이 일어나기 전에 실행됨
  - `onEach`
    - 업스트림 플로우에서 배출된 각 원소에 대해 작업을 수행한 후 이를 다운스트림 플로우에 전달함
  - `onEmpty`
    - 원소를 배출하지 않고 종료되는 플로우에 로직을 추가로 수행하거나 기본값을 제공
  - `buffer`
    - 기본적으로 값 생산자는 수집자가 이전 원소를 처리할 때까지 작업을 중단함
    - 버퍼를 추가해서 다운스트림 플로우가 이미 배출된 원소를 처리하느라 바쁜 동안에도 업스트림 플로우가 원소를 배출할 수 있게 할 수 있음
    - 생산자와 수집자의 연결을 분리
    - 플로우에서 원소를 배출하고 처리하는 데 걸리는 시간이 변동될 때 단위 시간 동안 처리량을 늘리는 데 도움이 될 수 있음
    - `onBufferOverflow` 파라미터: 버퍼 용량이 초과될 떄 행동 지정 가능
  - `conflate`
    - 수집자가 바쁜 동안 배출된 항목을 버림
    - 플로우가 최신 값을 배출하는 형태일 경우 수집자가 최신 값을 받아볼 수 있음
  - `debounce`
    - 업스트림에서 원소가 배출되지 않은 상태로 일정 시간 유지 시에만 항목을 다운스트림 플로우로 배출함
    - 예시) 검색어 입력
  - `flowOn`
    - 코루틴 콘텍스트가 플로우 로직이 실행되는 위치를 결정함
    - 수집 프로세스는 `collect`가 호출된 콘텍스트에서 실행됨
    - 파이프라인의 일부를 다른 디스패처나 다른 코루틴 콘텍스트에서 실행하고 싶을 때 사용하는 연산자
    - flowOn 연산자는 업스트림 플로우의 디스패처에만 영향을 미침
  - 커스텀 중간 연산자
    - collect 로 업스트림 플로우의 원소를 수집
    - flow 빌더 함수와 emit을 활용해서 새로운 다운스트림 플로우를 생성하는 방식으로 구현 가능
- 최종 연산자
  - 중간 연산자는 주어진 플로우를 다른 플로우로 변환하지만, 실제로 코드는 실행하지 않음
  - 플로우의 실행을 담당
  - 항상 일시 중단 함수
  - `collect`
  - `first`, `firstOrNull` 처럼 특정 조건이 되면 알아서 업스트림 플로우를 취소할 수도 있음

# 궁금했던 것들
### flowOn 연산자는 코드상 위쪽에 위치한 플로우에 영향을 주는 방식인데, 코드를 위에서 아래로 읽는다는 것을 고려하면 이질적인 시스템이 아닌지? 왜 굳이 본인 위쪽에 영향을 주게끔 설계된 것인지?
- 플로우가 실행될 때는 역순으로 파고드는 방식이라 시스템상 아래쪽에 배치해야 함
